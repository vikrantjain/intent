# Distinctions

Four distinctions carry the work. Everything else is judgment.

## Problem vs. solution

A problem says what is wrong now and for whom. A solution says what to build. "Add a cron job"
is a solution. "Reports have to be on the desk before 9am and nobody is awake to run them" is a
problem.

A request can name a solution and still be fine. What matters is whether the problem behind it
is recoverable. If the user can state it when asked, nothing was lost. If they cannot, the
solution was never checked against anything, and it is the first thing to establish.

Note the difference between a user who chose an approach after thinking, and one who reached for
the first thing that came to mind. Both sound the same in writing. Asking why this approach
separates them in one exchange.

## Constraint vs. preference

A constraint holds whoever is doing the work: a deadline, a regulation, a system that already
exists and will not change, a budget. A preference is the user's taste or habit, and it can bend
if something better shows up.

Users routinely present preferences as constraints, usually without noticing. The cost is that
every option incompatible with the preference silently disappears. When a stated constraint has
no source outside the user, ask what happens if it does not hold. The answer sorts it.

## Stated vs. assumed success

Success is stated when someone other than the author could tell, from the request alone, whether
the result is right. Most requests do not clear that bar. "Make it faster" and "clean this up"
carry a standard in the user's head that never reached the page.

This is the single most useful thing to recover, because it is what later work gets checked
against.

## Room left for the agent

A brief either invites the agent's judgment or forecloses it. Foreclosure is not always wrong:
sometimes the user has decided, and execution is what they want. It goes wrong when it is
accidental, when the user would have welcomed a better approach and never signalled it.

Read what the request permits. If following it exactly leaves no point at which the agent could
have proposed something different, that is worth saying out loud.
